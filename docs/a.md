🔹 ✔️ Domain Model Contracts

این یعنی قرارداد داده‌ای بین اجزای سیستم.
دو نوع مهم
📍 1. External Contracts

این قراردادها مشخص می‌کنند که چه داده از Basalam گرفتیم.

مثال:

    Basalam webhook event schema

    Basalam product payload schema

    Basalam order event payload schema

این‌ها باید در کد به صورت Pydantic models پیاده‌سازی شوند تا هر payload Validate شود.
📍 2. Internal Domain Contracts

این مشخص می‌کند که داده در داخل سیستم چه شکلی است.

مثال:

class Product(BaseModel):
    id: UUID
    title: str
    description: str
    variants: List[Variant]

این internal contract باید از external contract جداسازی شود تا اگر API خارجی تغییر کرد، کل سیستم نشکند.
📌 چرا جداسازی مهم است؟

✔ security
✔ versioning
✔ ease of mapping external to internal
✔ ability to transform payloads
🔹 ✔️ Database Migration Plan

قبل از start coding باید استراتژی migration مشخص شود.
🎯 هدف

هیچگاه اسکیمای DB نباید دست‌کاری مستقیم شود؛ همه تغییرات باید از طریق migration scripts اعمال شوند.
📌 ابزارهای رایج

✔ Alembic (برای SQLAlchemy)
✔ Flyway
✔ Liquibase
✔ Django migrations (اگر Django استفاده شود)
📌 ساختار migration (example)

migrations/
  ├── versions/
  │     2026_03_18_initial.py
  │     2026_04_01_add_order_status.py
  │     2026_04_10_add_foreign_keys.py

هر فایل migration باید:

✔ در تکرارهای بعدی قابل replay باشد
✔ معکوس پذیر (rollback) باشد
✔ در CI/CD اجرا شود
📌 مراحل migration strategy قبل از coding
1. تعیین baseline schema

اولین چیزی که مشخص شود باید جدول‌های اولیه باشد (همان ERD).
2. تعیین naming convention

مثال:

tbl_products
tbl_orders
tbl_order_status

3. ساخت versioning plan

مثلاً:

v1 — core tables
v2 — product sync enhancements
v3 — webhook logs
