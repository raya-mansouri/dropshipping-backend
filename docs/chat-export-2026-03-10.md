### Assistant

چیزی که توضیح دادی در واقع یک**پلتفرم Dropshipping / Marketplace Sync System**است. هسته اصلی سیستم هم همان‌طور که خودت گفتی**سینک قیمت و موجودی + مدیریت سفارش بین چند تامین‌کننده و فروشنده**است.اگر از اول درست طراحی نشود بعداً تبدیل به جهنم می‌شود، مخصوصاً در**مدل داده و event flow**.

من پیشنهاد می‌کنم پروژه را در**۶ لایه اصلی**طراحی کنیم. بعداً می‌توانیم هر کدام را عمیق‌تر باز کنیم.

# 1️⃣ Actor ها (Roles)

اول باید مفاهیم را یکی کنیم.

**Actors اصلی:**

1️⃣**Supplier (تامین‌کننده)**

- اتصال به غرفه باسلام
- یا آپلود دستی
- یا CSV / Sheet
- تعیین قیمت پایه
- تعیین هزینه ارسال
- مدیریت موجودی

2️⃣**Seller (Dropshipper)**

- محصولات تامین‌کننده را انتخاب می‌کند
- روی آنها مارکاپ قیمت می‌گذارد
- در سایت خود می‌فروشد
- سفارش‌ها را پرداخت می‌کند

3️⃣**Platform (سیستم شما)**

- سینک دیتا
- مدیریت سفارش
- مدیریت پرداخت
- مدیریت نوتیفیکیشن
- مدیریت کاتالوگ

# 5️⃣ مهم‌ترین چالش پروژه

این پروژه ۳ مشکل اصلی دارد:

## 1️⃣ Price Sync

قیمت‌ها باید زنجیره‌ای باشند
```
Supplier Price      +Supplier Commission      +Seller Margin      =Final Price
```

باید snapshot بگیریم.

در Order باید ذخیره شود:
```
supplier_price_at_orderseller_price_at_orderplatform_feeshipping_cost
```

## 2️⃣ Inventory Sync

بدترین قسمت سیستم همین است.

باید این مدل را داشته باشیم:
```
Available InventoryReserved InventorySold Inventory
```

وقتی سفارش ایجاد می‌شود:
```
reserve inventory
```

وقتی پرداخت شد:
```
confirm inventory
```

اگر cancel شد:
```
release inventory
```

## 3️⃣ Variant Explosion

اگر محصول variant داشته باشد:
```
Tshirt   ├── Red / L   ├── Red / M   ├── Blue / L
```

پس باید این مدل داشته باشیم:
```
ProductVariantInventory per VariantPrice per Variant
```
